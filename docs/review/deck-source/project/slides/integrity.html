Layer 1 · HTTP

Same key, same answer

Stored response replayed; no second debit.

Layer 2 · Business

One live payment per QR

A second tap with a new key gets 409 and the payment to follow.

Layer 3 · Ledger

Each posting at most once

UNIQUE(txn, posting type) plus row locks.

Layer 4 · Rail

Resend the same E2E id

Only after the rail says NOT_FOUND.

Timeout = PENDING, never FAILED (ADR-006). We ask the rail at 5 s → 5 min. After 15 min a human owns it, and any reversal is maker-checker.

Proof: tests S2, S3, S4, S5, S11; concurrency test passed 5/5 runs

Speaker B. Every transition is optimistic-locked, written to history and to the outbox in one transaction. Four layers of idempotency, each for a different failure. The key point for the viva: a timeout is an unknown outcome. Refunding on timeout is how both customer and merchant end up paid. Load testing found a race between our dispatch and the worker; constraints held, and we fixed it with row locks and an atomic claim.
