Speaker B (Taha). Every payment moves through these steps, and each step is saved together with an event in one database transaction. We protect against double charging at four levels: the same request twice gives the same answer; one QR can only have one live payment; the database refuses the same ledger entry twice; and if Raast's reply is lost, we ask Raast what happened and resend the same payment ID only if it never arrived. The key point: a timeout means we don't know yet. If you refund on a timeout and Raast did pay, both the customer and the shop end up paid. After 15 minutes a person takes over, and any refund needs two people.
