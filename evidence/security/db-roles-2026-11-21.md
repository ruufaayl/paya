# Database role split: run against the real Docker Compose stack (2026-11-21)

Stack: `docker compose -f infra/docker-compose.yml --env-file .env.example up` (isolated project name), image built from `infra/Dockerfile.api`. See ADR-015.

## 1. The one-shot migrate job ran as the owner

```
migrate-1  | {'revision': '0002', 'stamped_legacy_database': False, 'app_role': 'paya_app'}
```

## 2. The API connects as the app role only

Client connections to database `paya` while the API was serving, excluding the query's own session (`pg_stat_activity`, as `usename|application|connections`):

```
paya_app||2
```

The API container's environment holds only the `paya_app` credentials (`PAYA_MIGRATE_ON_START=false`); it checks the schema is at head and refuses to start otherwise.

## 3. A real payment works through the API on the app role

`POST /v1/payments` → `PAYA-20261121-49C838`: PENDING on the response, then **SETTLED** by the worker (checked in `transactions`); 16 ledger rows in the database.

## 4. What the app role cannot do (psql as `paya_app`)

| Statement | Result |
|---|---|
| `UPDATE ledger_entries SET amount_minor=1` | ERROR:  permission denied for table ledger_entries |
| `DELETE FROM audit_log` | ERROR:  permission denied for table audit_log |
| `ALTER TABLE ledger_entries DISABLE TRIGGER ALL` | ERROR:  must be owner of table ledger_entries |
| `DROP TABLE audit_log` | ERROR:  must be owner of table audit_log |
| `TRUNCATE journals` | ERROR:  permission denied for table journals |
| `CREATE TABLE sneaky(id int)` | ERROR:  permission denied for schema public |

The append-only triggers remain as a second wall: even the owner gets `APPEND_ONLY` on an UPDATE of `ledger_entries` (test `test_ledger_is_append_only_and_unbalanced_journals_are_refused`).

Automated equivalents: `tests/test_migrations_roles.py` (M1–M6). The whole backend suite also runs as `paya_app`.
